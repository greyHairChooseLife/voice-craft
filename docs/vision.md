# 비전

이 프로젝트가 **무엇**이고 **왜** 하는가. "어디로 가는가"는 [roadmap.md](roadmap.md), "어떻게 생겼나"는 [architecture.md](architecture.md), 결정 이유는 [decisions.md](decisions.md).


## 아이디어

스타크래프트는 컨트롤(피지컬)과 전략/판단력이 동시에 요구된다. 생산 관리와 전투를 같이 해야 한다.

이 게임을 즐기지 못했던 이유는 "쌓아놓은 게 한 번에 물거품"이 되는 스트레스. 그래서 입으로(말로) 하면, 또는 손으로만 하되 명령은 음성으로 받으면 재미있을 것 같다는 발상.

원래도 음성 알림("베스핀 가스가 부족합니다" 등)과 미니맵 하이라이팅이 있지만 충분치 않다. 실제 지휘관처럼 정보를 음성으로 받고 판단만 하는 게임이 가능할 것.


## 게임 모드 (참고용)

세 가지 가능 형태. 본체는 모드 2.

-   **모드 1 — 역할 분담 (Dual Operation)**: 한 진영을 둘로 나눠 한 명은 생산, 한 명은 전투. SC2 집정관 모드와 동일.
-   **모드 2 — 음성 명령 (Voice-Only Command)**: 마우스/키보드 없이 음성으로만 게임 운영. **이 프로젝트의 본체.**
-   **모드 3 — AI 부관 브리핑**: 플레이어는 직접 조작, AI가 실시간 정보 격차를 음성으로 메움.


## 프로젝트 정체성

-   **완성 형태**: 도구 (Tool).
-   **사용자**: 콘텐츠 씬을 활용하려는 개발자 (본인). 콘텐츠 제작 본업 아님.
-   **우선순위**: 화제성 7 : 학습 3. 콘텐츠 씬에서 주목받을 무기.
-   **제약**:
    -   재배포 가능해야 함 ("5분 안에 설치되고 동작" — MVP 이후 단계의 목표).
    -   맵 에디터로 쉽게 되는 건 굳이 어렵게 안 함.
    -   흥미 없는 문제는 안 풀음.
-   **방향**: 결과 우선. 핵심(엔드-투-엔드 파이프라인)부터 돌리고, 그 다음에 기술 디테일을 단계별로 판다.


## 안전장치

-   **멀티플레이 자동 비활성**: 도구가 게임 모드 감지 → 멀티 감지 시 자동 비활성 또는 경고.
-   **공식 권장 환경**: 싱글, VS 컴퓨터, 리플레이 분석.
-   Blizzard EULA / Battle.net Warden 리스크 완화 목적.


## MVP 이후 (확장 후보)

-   명령 종류 확장 (일꾼/메딕/건물/업그레이드…).
-   다른 종족 (저그/프로토스).
-   전투 명령 ("1번 부대 앞마당 공격") — 동적 좌표 처리 필요.
-   NLU 업그레이드: 로컬 LLM (Llama 3 / Qwen / EXAONE 등) + JSON Schema 검증 레이어. 타겟: GPU 8GB+ VRAM.
-   VAD (Voice Activity Detection) — 푸시-투-토크 대체.
-   배포 패키징 ("5분 안에 설치").
-   로컬/사설 서버 셋업 가이드 또는 자동화 (Shieldbattery 등). "친구들이랑 입스타 토너먼트" 콘텐츠 시드.
-   모드 3 (AI 부관) 추가.
